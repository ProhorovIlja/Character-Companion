# Mandy AI — token-aware native context fitting

Native generation now reserves the configured response token budget before decoding. It first renders and tokenizes the complete bounded candidate prompt with the selected model's existing chat template and vocabulary. On rendered-byte or token-budget overflow it geometrically reduces the older history suffix and retries, retaining the system message (including supplied character identity and selected memory context) and newest user message intact. After trimming, it advances past leading assistant messages to a user boundary. It never changes stored conversation events. Required context that cannot fit fails before inference with an explicit IOException. A template error or empty tokenization fails closed. Cancellation is checked between attempts, not inside a template/tokenizer call. Training-context validation is performed before fitting. The JNI V2 signature, CPU preset controls, memory admission, output cap, sampler and resident model lifecycle are unchanged.

The geometric reduction is intentionally bounded rather than an exact longest-fitting-suffix search. At most nine render/tokenize attempts are needed for the existing 201-message input cap. It can discard more older context than strictly necessary. Existing Kotlin prefilter limits (including the default 12,000 UTF-16 unit conversation selection budget) remain, so this is token-aware fitting of the supplied candidate only, not unrestricted history retrieval or an implementation of KV cache reuse. It does not resolve templates that require unsupported formatting, model-specific reasoning controls, oversized mandatory identity/messages or context beyond the trained model limit. It does not rewrite or summarize memories. A new prompt is built each generation. Assessment prompts containing only system plus user are never shortened by this mechanism. Real English/Russian token efficiency and latency need device benchmarks.

Validation: exact modified production C++ bridge compiled against the existing test-only llama API fixture under clang++ C++17; Kotlin host suite compiled and run with JVM -Xcheck:jni. 36 checks passed (29 existing plus 7 additional), including positive token overflow, negative tokenizer capacity result, template output overflow, retained recent user/assistant pair and intact Russian system message, mandatory-context rejection, cancellation during fitting and successful subsequent inference fixture. Existing resident-model and durable-turn jars were run against the newly compiled JNI library: 26 and 18 checks passed respectively. Total 80 counted assertions. Fixture tokenizer and renderer simulate overflow, not actual vocabulary segmentation or neural inference.
