# Browser session continuity and OAuth boundary
The browser-owned Character.AI session now saves only the sanitized launch destination in the Android Activity bundle. Restored activities ignore stale Intent extras and never automatically relaunch the Custom Tab. Fresh launches and new intents still accept a sanitized public destination. Failed transitions restore the original browser-session preference rather than forcing an arbitrary mode. The state is the requested launch address, not browser history or the current URL inside a Custom Tab.
Sources reviewed: Android saved state https://developer.android.com/topic/libraries/architecture/views/saving-states-views ; RFC 8252 https://datatracker.ietf.org/doc/html/rfc8252 ; Google embedded user-agent policy https://developers.googleblog.com/upcoming-security-changes-to-googles-oauth-20-authorization-endpoint-in-embedded-webviews/ ; Character.AI login help https://support.character.ai/hc/en-us/articles/23628361893659-Trouble-logging-in-We-ve-Updated-our-Login-Process ; AppAuth https://github.com/openid/AppAuth-Android ; Mozilla Android Components https://github.com/mozilla-mobile/android-components ; Candy Browser https://github.com/sk2andy/candy-browser . No external code copied.
16 JVM checks passed using exact new policy and smoke test, exact existing UrlPolicy, and a minimal HostBlocker stub reproducing the two domain predicates used by UrlPolicy. No Android compilation or device tests. This does not transfer cookies, register an authorized OAuth redirect, or fix embedded Google sign-in. Native OAuth requires provider-authorized client and redirect configuration; no spoofing or credential transfer implemented.
