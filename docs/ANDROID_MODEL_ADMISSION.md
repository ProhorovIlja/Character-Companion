# Mandy AI — conservative Android model admission

The independent Android workspace samples ActivityManager.MemoryInfo immediately after verifying the explicitly selected GGUF file and before loading the native engine. This protects both conversation generation and explicit relationship/memory assessment. It does not poll, schedule, monitor or start a background service. No new dependencies or permissions. Existing lower-level open callers can omit the optional admission callback; this is a workspace guard, not a universal native memory enforcement mechanism. Completed reply retry avoids loading the model and does not need admission. Refused generation leaves the persisted user message and pending retry intact; no character response is committed. Error details distinguish invalid metrics, Android low-memory state and conservative headroom shortage.

Policy: require positive model byte count and plausible system memory metrics. Required available bytes = GGUF file bytes + provisional 768 MiB workspace allowance + max(512 MiB, Android low-memory threshold). Reject if Android reports low memory or available <= threshold, or available < required. Arithmetic overflow fails closed. These values are intentionally conservative experimental estimates, not measurements, not an exact resident footprint, and not a guarantee against OOM. Memory-mapped models can require less physical memory, while KV cache, context, tensors, native allocations and competing apps can require more. The check may reject models which would otherwise run and memory can change after the check. No unsafe override, automatic model substitution, GPU/NPU acceleration or thermal tuning in this increment. A model/context-specific admission estimate and measured Pixel 8a benchmarks are next steps. No Windows change.

Design references: https://developer.android.com/reference/android/app/ActivityManager.MemoryInfo ; https://developer.android.com/topic/performance/memory/manage-app-memory ; https://github.com/ggml-org/llama.cpp/blob/master/docs/android.md ; https://github.com/ggml-org/llama.cpp/blob/master/tools/cli/README.md ; https://github.com/Siddhesh2377/llama.cpp-android/blob/re-write/docs/ARCHITECTURE.md . Reviewed available memory semantics, context costs and mmap approaches, not imported external code.

Updated EmbeddedLlama.kt, EmbeddedChatTurn.kt, EmbeddedChatTurnSmoke.kt compiled with current native character memory v2 and existing production JVM core; 18 assertions passed using the prior host JNI test double under -Xcheck:jni. The suite covers refusal before native model loading, preserving pending and user history, successful retry and completed retry bypass. No genuine GGUF inference was used. Host script updated, not executed as a whole. Android ActivityManager adapter and UI not SDK-compiled; no actual memory measurement or APK/EXE. No new scheduled or background operations.
