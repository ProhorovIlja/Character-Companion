# Mandy AI — native conversation storage and turn coordinator (2026-11-24)

Android production-source classes NativeConversation, AndroidConversationStore and AndroidLocalConversation connect the earlier local model transport to a native history contract. No Python runtime is required by these classes. Entry point accepts caller-owned stable account/device/character/chat/message IDs and character identity. User message is committed before inference; bounded same-chat context, streamed text, and final reply commit are distinct. The reply UUIDv5 matches the Python reference for the tested vector. Retry of an already completed message returns persisted text. Newer messages or conflicting concurrent replies reject stale final commits. Cancellation or provider failure normally preserves user text without a completed reply. Cancellation is cooperative, with a commit-boundary race; it is not immediate cross-thread interruption or spoken-audio accounting.

The Android SQLite helper uses a separate private mandy_history_v1.db, version 1, foreign keys, WAL, transactions, account binding, indexed keyset pages of at most 200 rows. No destructive schema migration; legacy browser storage unchanged. UUID account is a local namespace, not authentication. Database is plaintext inside the Android app sandbox; no encryption, import/export or sync implementation. Do not upload the database. Event schema follows v1, but cross-platform Unicode validation and interchange still require broader conformance tests. No real character profile, relationship/memory/research integration, UI session manager, or native inference engine in this change. Endpoint trust and existing Android cleartext policy remain unresolved; no manifest or networking permissions changed. No background jobs.

Validation: NativeConversation.kt and tests/NativeConversationSmoke.kt compiled on Kotlin/JVM 1.9.0 / JDK 21; 18 top-level checks passed using a test-only in-memory history and simulated provider (retry, isolation, invalid text, context limits, failed/cancelled/stale replies, UUID parity). Separately ran actual CREATE TABLE/INDEX statements extracted from AndroidConversationStore.kt in Python sqlite3 and checked schema creation, scoped keyset pagination and foreign key rejection. This does not test Android SQLite bindings, transaction lifecycle, disk reopen, or real Android concurrency. Android adapter and integration source not compiled (Android SDK absent), no actual LLM or APK/EXE. Limits provisional: 12,000 UTF-16 context units, 8,000 identity units, 16,000 reply units, max 200 context rows; not token budgets. Next gate: Android SDK compilation, instrumentation tests for database reopen/concurrency, actual chat UI and trusted embedded inference, then Windows native parity.
