# Mandy AI — embedded llama.cpp preview (2026-11-24)

Adds an optional direct JNI path with no HTTP, no external server, no runtime download and no cleartext policy changes. EmbeddedLlama verifies an explicitly selected private GGUF by SHA-256, loads one CPU model, and creates a fresh context and sampler per generation. Callers own model trust, lifetime, worker and resource budget. AndroidEmbeddedConversation connects the source API to the existing pending-send/history protocol, but the screen does not enable Send yet. No app startup model load. Explicit opt-in build only: supply -PmandyLlamaDir=<absolute local clean checkout of ggml-org/llama.cpp at dbaf582af41941ebbfc4384fb9fa1b40dff7a510> to the existing manual Gradle build, with NDK 29.0.13113456 and CMake 3.31.6 installed. ARM64 only. The source checkout is not downloaded or bundled by this change. CMake validates HEAD and git status, not full supply-chain integrity. No automatic jobs or update checks. Review upstream licenses and package notices before distribution.

Native code uses the pinned header's model load, built-in chat template, tokenization, batch decode and sampler APIs. It rejects encoder models, missing or unsupported templates, oversized prompts and token limits instead of silent context shifts. The built-in template helper is not a full Jinja implementation; Qwen compatibility, thinking-channel separation, role/control-token injection and chat-template fidelity are unresolved. CPU baseline, 4096 requested context, 512 output, four threads, top-k 40, top-p .9, temperature .8; all provisional, not hardware benchmarks. Fresh native context avoids retained KV across characters but costs prompt replay and context allocation. Model is held until explicitly closed; caller must own one engine per app runtime, no global memory admission controller. No real-model security, quality or latency claims. Native load is blocking, cancellation before/after load and between decode batches/tokens only; no immediate interrupt guarantee. Output ends successfully only at EOG. On truncation or cancellation the existing conversation contract retains user message but not a completed reply. Native exceptions are mapped to generic IOException unless a Java callback exception is already pending. No native logs by this bridge. JNI release keep rules added.

Verified locally: exact EmbeddedTextSink and smoke file compiled with existing NativeConversation; 51 checks passed on JVM, including every split boundary of multilingual text and emoji, invalid UTF-8, incomplete suffix, cancellation and limits. EmbeddedLlama compiled with the existing NativeModelLibrary and NativeConversation, and javap confirmed private native methods and public callback signatures. Actual C++/llama.cpp linking, NDK/Gradle compilation, Android device execution, ELF alignment verification and real model inference have NOT been tested. Container Git network unavailable and Android SDK/NDK absent. No APK/EXE generated. Existing default build remains without native dependency. Next gate: actual opt-in build and small licensed GGUF smoke test before enabling UI generation.

Upstream API inspected: https://github.com/ggml-org/llama.cpp/blob/dbaf582af41941ebbfc4384fb9fa1b40dff7a510/include/llama.h and https://github.com/ggml-org/llama.cpp/tree/dbaf582af41941ebbfc4384fb9fa1b40dff7a510/examples/llama.android. No upstream source copied.
