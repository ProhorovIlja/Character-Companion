# Mandy AI — native composer dictation preview

NativeDictation is a main-thread session coordinator. It snapshots the exact character/chat ticket, draft and caret/selection, uses the existing VoiceDraftPolicy and VoiceRecognitionOptions (rather than duplicating the legacy voice text-editing logic), accepts one terminal result, ignores stale callbacks, and rejects mismatched chat/draft, invalid or oversized transcripts. Explicit Stop keeps the draft; Stop · send records a one-time send request; provider endpointing alone never sends. Repeated dictation can append or insert at the caret. It does not retain audio, schedule work or run a microphone in the background.

MandyWorkspaceActivity adds in-place Dictate on device using Android API 31+ createOnDeviceSpeechRecognizer only. No generic/cloud recognizer fallback; EXTRA_PREFER_OFFLINE is also requested, but the platform service implementation and installed language packs must be validated on device. Existing RECORD_AUDIO permission and RecognitionService package query are reused. Permission grant does not start recording; a further explicit tap is required. Language selection uses existing supported language list, not a claim each pack is installed. Stops or cancellation destroy the session recognizer; onPause cancels. Inputs are suspended during recognition. On a valid final transcript, update editor and persist through existing workspace writer before considering a send. Stop · send is available only with experimental inference build, no pending retry, and imported model inventory. It then opens existing model selection and trust confirmation; it does not bypass trust or auto-submit. Generation uses dictation mode for that send. If model picker is cancelled, the saved draft remains. Natural endpointing saves an editable draft; it may happen before manual stop. No live voice, independent ASR engine, continuous listening, audio file recording or TTS yet. Process death before successful persistence can lose a transcript; the provider can fail or stall, with explicit cancel available. Android activity source uncompiled and device privacy/recognition behavior untested.

Research references, not imported code: Android SpeechRecognizer API (https://developer.android.com/reference/android/speech/SpeechRecognizer), RecognizerIntent (https://developer.android.com/reference/android/speech/RecognizerIntent), sherpa-onnx (https://github.com/k2-fsa/sherpa-onnx), Android dictation using Parakeet (https://github.com/boyoyooo/yoice), multilingual local ASR example (https://github.com/lighteningAB/ev-asr-demo), multi-engine comparison (https://github.com/voiceping-ai/android-offline-transcribe), sherpa-onnx fork (https://github.com/shubhendur/sherpa-onnx-SpeechToText), whisper.cpp (https://github.com/ggml-org/whisper.cpp). A platform-provided on-device recognizer is an interim dependency-free path, not a guarantee that Google speech services are available on LineageOS. Independent ASR remains necessary for consistent language support, latency, and Windows parity. Evaluate licensed multilingual Whisper and sherpa-onnx models on actual hardware before choosing.

Validation: exact NativeDictation.kt and NativeDictationSmoke.kt compiled on Kotlin/JVM with exact existing NativeConversation.kt, NativeChatWorkspace.kt, VoiceDraftPolicy.kt and VoiceRecognitionOptions.kt (Git blob hashes checked). 27 checks passed: first stop wins, natural completion does not send, successive dictation, send gating, ticket and draft isolation, duplicate/stale terminal callbacks, cancellation, invalid alternatives, overflow and surrogate-safe insertion. No microphone, Android SDK/NDK, native ASR, actual model inference, APK or EXE tested. No new dependencies or permission, no workflows or schedules.

Manual host reproduction: kotlinc the five production Kotlin files named above (including NativeDictation) with tests/NativeDictationSmoke.kt -include-runtime -d smoke.jar; java -jar smoke.jar.
