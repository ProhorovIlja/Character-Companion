# Standard CHARX text import
Both native studios detect ordinary ZIP local-header signatures and read the root card.json through a bounded streaming reader. Existing JSON/PNG and lorebook TXT import paths remain. Maximum consumed compressed bytes and expanded bytes: 64 MiB each; up to 512 local entries; card JSON up to 2 million UTF-16 code units and 6 million UTF-8 bytes. Strict decoding, duplicate root detection and cooperative cancellation. No assets are written or executed; only the card text enters the existing converters. Conversion is not a complete CCv3 round-trip. JPEG+ZIP hybrids, encrypted archives, embedded images/audio and archives above the limits are unsupported. ZIP local-entry stream is checked; central-directory consistency is not separately validated.
References: https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md ; https://github.com/character-foundry/character-foundry/blob/master/docs/charx.md ; https://github.com/character-foundry/character-architect ; https://github.com/overworks/chara-snap-enhanced ; https://github.com/zer0thgear/ultimate-character-card-builder ; https://developer.android.com/training/data-storage/shared/documents-files . Independent implementation, no new dependencies.
13 focused JVM checks executed using the reader and a stub containing the existing MAX_CHARS constant. Full Android compilation and provider/device testing remain outstanding.
