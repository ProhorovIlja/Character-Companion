# Mandy AI — expanded native character memory

Capacity grows from 32 to 128 notes per character; each note remains limited to 400 UTF-16 units. The existing identity, relationship, pinned note, revision and character/account scope are preserved. The binary record uses the original v1 magic for <=32 entries and v2 magic for larger records, with a 170,000-byte safety ceiling. Both formats are readable by this revision. A v1 file claiming >32 notes is rejected; older app versions cannot open a v2 record until it is explicitly reduced to <=32 notes by the newer app. No destructive migration, eviction, background indexing, dependency changes or cloud upload.

Retrieval normalizes text with NFKC and Locale.ROOT lowercase, removes a small English/Russian stop-word set, and ranks unique query terms with inverse document frequency weighting: sum(1 + ln((N+1)/(df+1))). Ties preserve original list order. This is lexical retrieval, not embeddings, stemming, semantic reasoning or measured recall quality. Still at most four relevant notes per turn, within the unchanged 8,000 identity / 12,000 combined UTF-16 budget. Model assessment and Android editor use the expanded limit; the editor is still a simple multiline preview, not optimized for large libraries.

Validation: 20 new checks passed using real temporary files, independent v1 fixture, large CJK records, v2 reopen and revision checks, v1 return, weighting, normalization, stopwords, deterministic ties, scope and prompt budget. Existing 23 memory, 18 relationship and 25 memory extraction checks passed after recompiling with the new core (86 total across four suites). The assessment capacity fixture uses MAX_MEMORIES. Kotlin JVM checks, not Android SDK or real-model inference. Host script includes the new suite, but complete script not rerun. Android editor source is not SDK-compiled. Limits are provisional; not unlimited memory. No APK/EXE or scheduled tasks. Build environment still lacks Android SDK/NDK and real inference validation.
