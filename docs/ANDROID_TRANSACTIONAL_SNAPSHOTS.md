# Mandy AI — native transactional history snapshots

HistoryManifest now has an internal consumeVerified path that authenticates the manifest, checks ordered per-page descriptors, and passes a private copy of each verified ciphertext page to a caller. The exact checked bytes are decrypted and parsed by HistorySnapshot; no verify-then-reopen dependency. HistorySnapshot requires separate 32-byte history and manifest keys. It exports bounded nonempty pages of at most 64 events, stages ciphertext copies, and returns a manifest only after all pages succeed. The snapshot cap remains 4096 chunks. A failed export may leave unpublished staged ciphertext: caller must discard it, and publish only after successful return. No staging filesystem/UI is implemented here.

AndroidConversationStore now uses a single existing SQLite write transaction for complete import and export. Import authenticates and decodes each chunk, merges immutable IDs, rejects conflicts/ownership violations and advances the clock. Missing, extra or invalid late chunks throw before the transaction is marked successful. Export traverses ascending keyset pages from the beginning under one transaction, holding the writer lock for consistency. Local staged ciphertext only; never download, perform network I/O or call back into the database from these APIs. Large snapshots may block writers; benchmark and implement resource/cancellation limits before release. No schema change. No full snapshot rollback protection, deletion semantics, profile/relationship transfer, key provisioning or cloud upload. Replay of identical events is intended to be idempotent. These are internal experimental APIs, not a user-facing backup feature.

Validation: exact HistoryManifest.kt, HistorySnapshot.kt and HistorySnapshotSmoke.kt compiled with existing HistoryWire, EncryptedHistoryEnvelope and NativeConversation on Kotlin/JVM. 25 new checks passed with a transaction double, including late missing/extra/altered/reordered chunks, wrong keys/accounts, authenticated invalid payload, conflict rollback in fixture, replay, empty snapshot, invalid export pages and staging-copy isolation. Existing 16 manifest checks recompiled and passed, and Python/Kotlin fixture manifests remained byte-identical (cmp). Android store adapter reviewed in source only; SQLite transaction behavior on Android and actual resource use not tested. No SDK/NDK build, APK, EXE, actual user data, remote transfer, workflows or scheduled tasks.
