# Windows native conversation turn coordinator (source preview)

LocalChatTurn connects the existing LocalHistory store and LocalInferenceClient. A caller supplies an explicit account/device/character/chat/message UUID, text, identity, mode and bounded context. The user message is durably appended before local generation; completed retries return the validated existing reply without another model request. Context is scoped to a contiguous recent suffix of up to 200 messages, capped at 12000 UTF-16 units by default (not actual model tokens); a leading orphan assistant is dropped. The coordinator rejects simultaneous calls to the same instance and checks the latest user before inference and again in the final SQLite transaction. Failed, cancelled or stale inference leaves the user message recoverable and does not save a partial reply. A cancellation racing the final commit may still produce a durable reply. The existing HTTP provider is restricted to an explicitly started trusted numeric loopback server. No service startup, remote fallback, monitoring, scheduled work or detached operation. Callers await the explicit Task; preview callbacks run on a worker and must be marshalled and scoped by the future WPF UI. No WPF hookup, draft persistence, cross-instance generation lock, profile management or encrypted sync added. No transaction remains open during inference. Model-specific token fit remains unverified.

Microsoft documents that Microsoft.Data.Sqlite's asynchronous APIs execute synchronously, so this explicit operation uses Task.Run to avoid blocking the future UI; it does not rely on fake asynchronous database calls. Existing SQLite dependency and schema unchanged. Added explicit System.IO imports to native store/client because WPF implicit imports may differ from console smoke builds. The HistorySmoke project now links all three production files and contains additional real-file tests with synthetic inference delegates for completion, completed retry, failed/cancelled generation and concurrent conversation advance.

Validation: the existing Python reference suite was actually rerun and passed 46/46 (Linux host, 10.502 seconds); it does not validate these C# changes. The .NET SDK remains absent; the native code and expanded smoke project have NOT been compiled or executed. No APK/EXE, real CUDA/model benchmark, Windows runtime result or new dependency. Manual smoke command: dotnet run --project windows/HistorySmoke/CharacterCompanion.HistorySmoke.csproj . Next gate is actual .NET restore/compile/test, then WPF integration on a verified build.
