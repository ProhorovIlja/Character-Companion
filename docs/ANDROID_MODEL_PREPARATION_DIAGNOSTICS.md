# Mandy AI — foreground model preparation diagnostics

Complements the eight native generation measurements with the following per-turn values: full file verification duration, memory admission duration, native model opening duration and whether the already verified resident engine was reused. Uses System.nanoTime, reports zero loading time on actual reuse, and never avoids the full SHA-256 verification or changes memory admission. Verification includes the existing library checks and hashing, not a standalone SSD throughput benchmark. Loading includes native library initialization when necessary. Switching and releasing the previous model, database commits and UI refresh are excluded; these are stage timings, not complete end-to-end latency.

The existing ResidentModel.useModel contract is preserved; useMeasured adds a success callback after the generation action returns and cancellation is checked. Chat generation uses the same path with either the existing resident session or a temporary session that closes after the action. Completed reply retries perform no preparation. The Android workspace displays the measurements only after successful reply commit and refresh. A preparation callback is internal to the inference action, not a durable-commit notification. No history, export, polling, telemetry, background work, scheduled activity, automatic tuning or new dependency. No new JNI ABI.

Validation: exact modified ResidentModel.kt, EmbeddedChatTurn.kt and ResidentModelSmoke.kt compiled on Kotlin/JVM with the current V3 native fixture library. 39 resident-model assertions (13 new) and 18 durable-turn assertions passed under -Xcheck:jni. Tests cover cold and reused engine flags, zero load time on reuse, nonnegative timings, no report on failed action, cancelled operation or refused memory admission, and reload after failure. Test backend does not run a neural model or measure real-world speed. Android UI source reviewed but not SDK-compiled. No actual Android/Windows measurement, performance gain, APK/EXE, cloud upload, background monitoring or scheduled task.

Next meaningful measurement: an explicitly started real-device inference session with a supported, trusted GGUF and full native build. Compare verification/loading/prefill before deciding whether a file-integrity cache or architecture-specific KV reuse is worth pursuing. Keep strong integrity checks until a validated immutable-storage design exists.
