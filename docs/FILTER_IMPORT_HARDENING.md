# Filter import compatibility and snapshot efficiency

Manual WebView rule imports and private stored rule loads now share a strict UTF-8 decoder. Invalid bytes fail the read instead of being silently replaced; the import confirmation is not reached on decode failure. Plain domain rows support whitespace-separated hash comments, but cosmetic selectors and unsupported ABP modifiers are not converted to whole-domain blocks. Existing sink-address hosts rows, critical-host exclusions and size limits remain. The filter compares settings with existing defensive snapshots before copying sets; unchanged configuration does not allocate fresh sets or rebuild the blocker. Equality checks still take O(n) for separately held large sets. No host cache or new request logging.

25 focused Kotlin/JVM checks passed on exact FilterEngine, RuleListParser and FilterImportSmoke files with existing HostBlocker and BoundedText. The engine test exercises 40,000 blocked domains plus one exception directly; parser import limits are unchanged (40,000 combined). Full Android build, full suite, device performance profiling and runtime import-provider checks are not done. This path applies to the WebView filter, not GeckoView's separate filtering capability or browser-owned Custom Tabs.

Companion treats imported hosts as suffix rules (uBO-style, not exact-only DNS mappings). No upstream source or lists bundled, no new dependency, no automatic fetch.
