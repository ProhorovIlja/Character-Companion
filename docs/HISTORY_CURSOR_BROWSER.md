# Bounded conversation history and indexed cursor seeks

The Android store now expresses older-message and forward export cursor predicates as SQLite row-value comparisons (clock,id). This matches the existing index order, removes a redundant clock bind, preserves exclusive cursor boundaries and deterministic ties, and avoids scanning large earlier portions of an index on the tested SQLite planner. No schema or index migration. Android minSdk 29 is above the documented API 28 SQLite 3.22 baseline, and row comparisons were introduced in SQLite 3.15. Actual ROM planner and compatibility still require device validation. Existing Python history page already uses this form, so no Windows reference change needed.

A new explicit Browse conversation history button opens a read-only dialog scoped to the selected conversation. It retrieves 31 rows on the existing serial worker, displays up to 30 chronologically, and uses the last displayed row's cursor for the next older page. Latest restarts from the newest page. No accumulating list, no offset scans, no draft replacement or model changes, no new package, network request, background polling or scheduled operation. Closing the dialog or invalidating its ticket suppresses stale results. The browser uses a bounded simple native view, not RecyclerView virtualization; screen layout, scroll behavior, accessibility, actual runtime memory and lifecycle behavior are unverified. Each page is a fresh read; concurrent history imports may affect traversal, not a consistent snapshot. The existing encrypted snapshot export retains its transaction.

Host SQLite 3.46.1 validation: five actual tests passed, on 60,000 synthetic in-memory messages across two chat IDs, including duplicate clocks and Unicode. String-bound SQL parameters mirror Android rawQuery. The old OR predicate and new tuple predicate returned identical tested rows. Deep history page of 30: approximately 334,800 vs 500 SQLite VM instructions; deep forward export page of 64: approximately 359,100 vs 1,000. Counts are sampled by a progress callback every 100 VM instructions, not wall-clock timings, Android speedups, energy measurements or user data. Tests use equivalent SQL directly, not the Android runtime. The exact tested Python test blob is checked before publishing. Run manually: python -m unittest discover -s tests -p test_history_seek.py.

RecyclerView remains a candidate for the eventual full conversation UI; the bounded dialog deliberately avoids introducing a new dependency before a real build. No third-party code copied, SDK/NDK still unavailable, no APK or EXE, no Windows production change.
