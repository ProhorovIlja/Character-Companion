# Android 0.34.0-rc1: browser-owned Google / Apple sign-in mode

The previously compiled 0.33.0-rc1 can open Character.AI in a system browser but cannot transfer that browser's authenticated cookies to the embedded GeckoView or WebView. Returning to the renderer can therefore appear logged out. Google OAuth does not support an app-controlled embedded user agent. This third-party client does not control Character.AI's OAuth registration or redirect endpoints.

The new explicitly selected browser-session mode opens the official site in a Custom Tab provided by the preferred compatible browser. The native Activity remains a dedicated session screen when the tab closes. Use Continue Character.AI session to reopen the browser-owned login; the same browser profile must remain signed in. The mode choice is stored as a local boolean, not a token or login claim. Both Gecko and WebView builds expose the mode from settings and known identity-provider prompts. The WebView native workspace also exposes the button. A switch back to the embedded renderer does not copy authentication. The browser owns all cookies and page content. No new exported login callback, private API, or OAuth token/cookie bridge. No relaunch on Activity resume. No automatic triggers.

**Limits:** this is not native Google sign-in inside GeckoView/WebView. Browser tabs cannot use Companion's native filtering, in-page voice integration or screen-protection flag. The browser's own privacy controls apply. An embedded session requires a sign-in method supported by the website in that same renderer; email verification is officially offered, but exact verification-link handling and real-device behavior need testing. Do not copy OAuth URLs or tokens into the app or logs.

References: [Google OAuth policy](https://developers.google.com/identity/protocols/oauth2/policies), [Android Custom Tabs](https://developer.android.com/develop/ui/views/layout/webapps/overview-of-android-custom-tabs), [Character.AI login help](https://support.character.ai/hc/en-us/articles/23628361893659-Trouble-logging-in-We-ve-Updated-our-Login-Process).

QA: fresh install, Google login and return; close tab and reopen; already signed-in default browser; app restart; rotate/recreate during sign-in; change default browser or no Custom Tabs provider; switch back to embedded; shared public links; cancel sign-in; no secret persistence or login-success claim. Actual Android compile and device sign-in pending a new manual workflow.
