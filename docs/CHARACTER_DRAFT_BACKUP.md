# Portable character draft backup (CCBK v1)
Explicit per-draft export and restore, using Android Storage Access Framework. Import character card detects CCBK by magic, not the extension. Format: magic CCBK, big-endian version 1, payload byte count, SHA-256 digest (32 bytes), then existing CCDR v1 payload. Decode rejects bad lengths, checksum mismatch, trailing bytes and unsupported versions. All currently represented fields, tags, alternate greetings, notes and conversion flag round-trip. This is not encryption, authentication, standard CCv3 export, full-library backup or a cloud synchronization service. User chooses destination; an external provider can retain the plaintext backup. Pending export bytes retained across configuration changes, not process death; no persistent URI grants. No new dependency or broad storage permission.
References: Android SAF https://developer.android.com/training/data-storage/shared/documents-files ; Android saved state https://developer.android.com/topic/libraries/architecture/views/saving-states-views ; Character Architect https://github.com/character-foundry/character-architect ; Card Forge https://github.com/thebestryan/card-forge ; Silly-Tavern-Explorer https://github.com/proto-deus/Silly-Tavern-Explorer . Independent format; no upstream code copied.
12 focused JVM checks executed against exact new codec/test and existing draft codec/policy, with a stub for LorebookPolicy.MAX_CHARS. Android compilation and provider lifecycle tests remain outstanding.
