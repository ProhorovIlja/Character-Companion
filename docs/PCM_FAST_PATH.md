# PCM16 direct-copy optimization

On Android, 16 kHz mono capture is already the Whisper input format. PcmSpeechBuffer now uses a bulk array copy for that case instead of executing the weighted resampler once per sample. Capacity expansion remains bounded and clears old buffers. The input is copied (not retained), so a reused microphone chunk cannot alter saved audio. Other sample rates retain the existing area-weighted resampler and rounding. Android capture must still verify the actual selected format; 16 kHz availability is not assumed.

Windows Pcm16Resampler now uses a bounded 16 KiB byte buffer for the equivalent 16 kHz mono PCM16 case. Stream.ReadExactly requires the stated byte count, so truncation is rejected and trailing data is not consumed. Output count and flush behavior remain consistent, and the temporary buffer is cleared in finally. Higher rates and stereo use the existing converter. Partial output on an I/O failure remains possible; the caller must discard incomplete WAV files, as StopAsync already does. Added two source-level smoke checks to the existing PolicySmoke project; these are NOT executed because the .NET SDK is absent.

Validation: 57 new actual Kotlin/JVM checks passed across full-length 180-second data, chunk boundaries, source buffer reuse, exact PCM output and capacity rejection. The prior 30 PCM smoke checks also passed (87 total). Exact two tested Kotlin blob hashes verified before commit. No actual speed, power, latency, Android runtime or Windows compilation measurement. The fast path removes redundant arithmetic; real device performance requires measurement. No dependency, audio format change, model, APK/EXE, scheduled operation or background service added.
