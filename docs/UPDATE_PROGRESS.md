# Foreground update transfer UX
The manual update download now shows actual byte-derived integer percentage, with at most one intermediate UI publication per 250 ms and a separate package/signature verification phase. The worker callback occurs after a successful write. A cancellation that occurs during a blocking read is checked before writing that chunk. Hash verification and the existing package/version/signing checks are unchanged; 100% transferred is not installation approval. GitHub rate limit responses (429 or 403 with rate-limit headers) have a separate message and do not trigger retries. No scheduler, polling, auto-update checks or new dependency.
References: https://developer.android.com/reference/android/widget/ProgressBar ; https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api ; https://docs.github.com/en/rest/releases/assets ; https://github.com/ImranR98/Obtainium and its release history. Independent implementation; no upstream source copied.
