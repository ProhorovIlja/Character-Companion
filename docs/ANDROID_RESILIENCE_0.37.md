# Android 0.37.0-rc1 — private draft resilience

Both embedded flavors retain an undelivered draft in a bounded in-memory recovery slot when reopening the private editor fails. A new explicit Voice tap reopens it, without automatic reinsertion. Activity recreation cannot inherit a prior insertion ticket. A new result cannot overwrite a pending or recoverable draft. Process death or closing the parent still clears the private in-memory slot; there is no disk storage or automatic clipboard use.

The voice editor confirms back navigation when a draft or recognition is pending, prevents copy/save/clear while recognition is pending, and adapts action layout for narrow windows or enlarged text. View-state saving and autofill are disabled for the editor; the IME receives the no-personalized-learning flag (a request, not a guarantee from third-party keyboards). The browser-session launcher handles failures without closing the source screen, retains the previous pinned browser if switching providers fails, and retains only a sanitized destination across configuration recreation. No auth tokens, cookies or private URLs are transferred. Renderer recovery deque handles Java nullable results explicitly.

No new dependencies, automatic triggers, recording jobs or hidden send actions. Real Android build and hardware QA remain necessary. Test on Pixel: empty and nonempty draft back; keyboard back gesture; narrow/large font action layout; recognition finish/cancel; failed insertion and recovery; rotation while browser session is open; missing browser provider; embedded mode switching; crash recovery. Stable signing and actual direct Google OAuth remain separate work.
