# Mandy AI — authenticated history transfer envelope v1

Experimental local-only building block for manual cross-device continuity. This is not live synchronization, a complete backup, or a production-ready key management system.

Wire format: 8 ASCII bytes MANDYH01, 12 random nonce bytes, ciphertext of an existing v1 history batch, then 16-byte authentication tag. AES-256-GCM using existing cryptographic library APIs, not custom cipher code. Additional authenticated data is exactly the 20-byte header followed by the canonical lowercase account UUID as 36 ASCII bytes (not stored in the envelope). Plaintext 1 through 4 MiB; 36 bytes overhead per chunk. No compression. Each account needs a dedicated uniformly random 32-byte key, shared securely with authorized devices only. Never use a password directly, use the fixture key in production, or reuse this key for other purposes. Nonces come from OS/platform CSPRNG; total encryption invocations under any one key across all devices must be conservatively bounded well below 2^32 and keys rotated. Usage tracking, secure pairing, key recovery, rotation, secure storage and key-memory lifecycle are not implemented. Do not upload actual personal data with this experimental path yet.

Python reference validates v1 JSON before encryption and after authentication, then delegates transactional import/immutable merge to HistoryStore. Each chunk is independently authenticated, not an authenticated full snapshot. Duplicate imports are idempotent and conflicting IDs roll back a whole batch. Missing chunks, reordering, rollback, replay of deleted data, provenance of individual writers, and deletion propagation require a manifest and additional protocol. Ciphertext size remains visible. The existing history and profile files remain plaintext locally. Only text history is covered, not character profiles, memory, relationships, drafts, media, or models.

Kotlin/JVM and Windows C# source implement the same envelope, using Java JCA and .NET AesGcm respectively, with no additional app dependencies. These APIs operate on bounded byte arrays, do not parse history and are not connected to native SQLite or UI. Android Keystore wrapping and Windows protected storage are future work. Python reference uses optional cryptography (tested 46.0.4); missing dependency causes its new unit suite to skip, not pass. No changes to existing workflows or network permissions.

Validation: seven Python unittest methods passed on real SQLite files, including replay, clock advancement, tampering and transaction rollback. Sixteen Kotlin/JVM assertions passed, including max-size roundtrip, wrong key/account, altered header/nonce/ciphertext/tag, truncation, oversize and Python ciphertext decryption. Separately decrypted Kotlin-produced ciphertext with Python and compared exact plaintext bytes. Test data synthetic multilingual message. C# source has not been compiled or interoperably tested because dotnet SDK is unavailable. Android SDK/NDK, APK, EXE, actual inference and Drive OAuth/sync remain unverified. No cloud upload, scheduled tasks or background jobs.

Manual reproduction from repository root with Python cryptography, Kotlin and JDK installed:
1. Run python -m unittest discover -s tests -p test_encrypted_history.py -v.
2. In Python use shared.continuity.encode and shared.encrypted_history.seal to produce a synthetic valid history batch and envelope with the fixture key bytes(range(32)) and account UUID 00000000-0000-0000-0000-000000000001. Save as fixture.json and python.enc in a temporary directory.
3. Compile NativeConversation.kt, EncryptedHistoryEnvelope.kt and tests/EncryptedHistorySmoke.kt with kotlinc -include-runtime -d smoke.jar, then run java -jar smoke.jar fixture.json python.enc kotlin.enc.
4. Use open_batch with the same test key/account to verify kotlin.enc is byte-identical to fixture.json. Never use actual personal data in this test.

References: https://csrc.nist.gov/pubs/sp/800/38/d/final and https://developer.android.com/privacy-and-security/cryptography . Before production use, review nonce/key lifetime and migration with the complete continuity protocol, and perform independent security review.
