# Mandy AI — native history wire and encrypted page transfer

HistoryWire implements the existing v1 JSON text-event contract on Kotlin/JVM, using strict UTF-8 decoding, exact root/event field validation, bounded nonrecursive parsing, duplicate-key rejection, positive integer clocks, UUID and text validation via NativeConversation.Event, deterministic ordering and immutable ID/chat ownership conflict rejection. Limits remain 2048 events and 4 MiB per batch. JSON field order differs from the Python writer but the decoded events are equivalent. No new app dependency. Whitespace-only string classification follows existing Kotlin text validation, which can differ from Python on some unusual Unicode whitespace characters.

AndroidConversationStore adds importEncrypted: authenticate then parse the whole batch before opening a SQLite write transaction; existing insert checks immutable conflicts/chat ownership and advances the clock. Duplicate identical messages are skipped. Any conflict aborts the batch transaction. exportEncryptedPage emits a single ascending 64-row keyset page, encrypted under the existing account-bound envelope. It is not a complete snapshot protocol: callers must serialize against writes during traversal; a permanent cursor would miss subsequently imported earlier events. No cloud, no key management, no UI exposure, no destructive schema migration. Imported messages may refer to characters not yet present in the profile library. Profile and memory transfer, authenticated manifest, completeness, rollback prevention, deletion and pairing remain outstanding. Do not use for actual private cloud sync yet.

Validation: exact HistoryWire.kt and HistoryWireSmoke.kt compiled on JVM with unchanged NativeConversation.kt and EncryptedHistoryEnvelope.kt. 26 checks passed: multilingual roundtrip, empty batch, malformed JSON/UTF-8, duplicate fields, invalid types/clock, unknown fields, surrogate validation, byte/event limits, conflicting ownership/IDs, encrypted roundtrip and Python fixture import. Python continuity.decode accepted the Kotlin-produced JSON and matched both decoded event lists. The Android adapter is source-only; no Android SQLite execution, SDK build, Windows compilation or real device tests. No APK, EXE, network upload or scheduled work.
