# Mandy AI — upstream evaluation and integration policy (2026-11-24)

The user requests broad internet/GitHub research and selective use of the strongest technologies for performance, quality, UI, efficiency, lightweight operation, stability and features on both Android and Windows. This supplements BILINGUAL_TARGET_DEVICE_ENGINEERING.md; English and Russian remain the only supported product languages. The following is an initial research register, not an assertion of exhaustive coverage, a dependency list, or a benchmark result. During each explicitly requested development increment, inspect relevant upstream documentation, releases, source changes, issues and useful forks before choosing implementation. No ongoing monitoring, scheduled activity, automatic downloads, background research or automatic upgrades. No unrelated OS/driver/ROM changes.

## Integration and quality rules

- Prefer narrowly scoped, maintainable improvements over collecting many overlapping dependencies. Keep inference, speech, retrieval, media, storage and UI behind replaceable interfaces. Use existing tested contracts rather than duplicate them.
- Check exact upstream revision, license (including model weights), transitive dependency obligations, vulnerability exposure, platform requirements, architecture, package footprint and maintenance burden. A fork is not automatically better or newer. Review its delta against upstream and prefer accepted fixes where possible. No unreviewed source, arbitrary binaries or incompatible license imports.
- Compare baseline versus candidate using identical model and quantization when technically possible; if comparing distinct models, also assess bilingual quality. Record cold/warm loading, verification, prefill, generation, peak RAM/VRAM, temperature, battery and failure recovery. Compare WER/CER and voice naturalness for speech, not just throughput. Reproducible foreground tests only.
- UI: Android and Windows share product structure, not necessarily implementation. Chats and Characters primary; native navigation, compact composer, dictation Stop/Send, clear cancellation, progressive response rendering, virtualized/paged history, accessible text scaling/keyboard, meaningful loading and error states. AMOLED dark theme on Android, restrained effects on Windows; no always-running decorative animation or redundant panels.
- Keep core functions local and independent of Google services. Optional user-initiated Drive sync and web/media retrieval require explicit authorization and data minimization. No silent cloud fallback, hidden telemetry, scheduled synchronization or auto-upgrade.
- Release readiness outranks speculative optimizations: compile and validate real Android ARM64 and Windows .NET builds, real inference and on-device chat, then independent speech, media, and continuity. A simulated backend pass does not count as a real hardware pass. Maintain one clear record of verified features and remaining blockers.
