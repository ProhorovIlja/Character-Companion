# Mandy AI — native character workspace preview (2026-11-24)

NativeCharacterLibrary persists independent account-scoped profiles with stable character and conversation UUIDs, editable name and identity, and multiple titled conversations. Records are bounded, versioned, atomically replaced and synced at file level. Invalid data is rejected instead of reset. A corrupt profile currently prevents listing the library; individual known IDs remain readable. Directory fsync, encryption, deletion, avatar/voice assets, profile revision conflicts and sync are not implemented. One writer instance per account is required. Temporary limits: 120 UTF-16 units for names/titles, 8,000 identity units, 256 chats per character, 160,000 bytes per profile.

MandyWorkspaceActivity is a native Android screen reachable via Module Center -> Mandy AI (offline workspace). It uses the existing dark/AMOLED theme, app-private local IDs, character and conversation picker, profile creation/editing, new conversations, most recent 50 persisted messages, and explicit draft saving. User-initiated switches save the current draft first. The screen uses a serialized disk executor; SQLite and file operations are not run on the main thread. No recurring or scheduled tasks. Unsaved drafts can be lost on unexpected process death; explicit save is required. Back prompts before leaving an edited draft. The preview is English-only; not the final UI, no avatars or voice, no history pagination UI. Send is disabled deliberately: no trusted embedded model is configured. No loopback cleartext permission is enabled, no external model or server is launched. Native inference and real streaming UI remain release blockers. The existing browser shell, package and launcher are unchanged.

Validation: NativeCharacterLibrary.kt and NativeCharacterLibrarySmoke.kt compiled on Kotlin/JVM with exact previously committed NativeConversation.kt and NativeChatWorkspace.kt; 17 counted checks passed using real temporary files, including restart, multiple chats, duplicate display names, namespace isolation, Unicode, invalid IDs and corrupt record detection. Android activity and manifest changes are source-only, not compiled or device tested. No APK/EXE. Run the four Kotlin files with kotlinc -include-runtime and java -jar. Android guidance: https://developer.android.com/training/data-storage/sqlite (disk access off main thread). No third-party code copied.
