# Local lorebook import and conversion

This native workspace is available from the overflow menu of both embedded engines and browser mode in the single ARM64 APK. It requires no Character.AI account to prepare documents. Character.AI's official Create → Lorebook → Import screen handles account-backed imports, linking and publication. The companion does not bypass subscription checks, upload files, publish lorebooks, inspect chats or inject prompts.

Supported input: UTF-8 structured TXT (including pasted text and .md files using the same labelled grammar), JSON entries maps and arrays, SillyTavern World Info, embedded character_book in CCv2/v3 JSON, and standalone lorebook_v3. Arbitrary unstructured TXT, ZIP, PDF, DOCX and YAML are not supported. Standard PNG character-card metadata import is now supported; see below. JSON uses the Android platform parser after a bounded nesting scan. Maximum 2 million decoded characters, 1000 entries, 256 keys per entry, 512-character title/key, 100,000-character content/description. These are local engineering limits, not service limits. Missing and excessive keywords are preserved and flagged; no silent truncation. Disabled source entries are skipped and counted; other metadata and activation features are not mapped and are flagged. Original files are not modified. TXT export refuses ambiguous fields; JSON export preserves name and description locally but the official editor may require entering those manually. Copy is limited to 100,000 characters. Use explicit Save to retain converted files in local or cloud document storage; current preview is memory-only, not a persistent lorebook database. No network, credentials or new permissions.

## Local creation and editing
Create a new draft, edit book name/description, add, preview, edit, duplicate or explicitly delete entries. The original imported document is unchanged. Search titles, keywords and contents with an explicit Search action (up to eight terms); the review-only filter flags missing fields, over-eight keywords and repeated case-insensitive keywords within an entry. Search results map back to original indices. Keywords use one line per key; untouched imported keys are preserved verbatim. Invalid edits leave the dialog open and retain the existing draft. A final entry cannot be deleted, but a new book can replace the draft. No silent truncation or deduplication. The preview remains memory-only; export before closing, which now requires confirmation. Reviewed https://github.com/SamYTTK/ST-EnhancedLorebook and https://github.com/ActualBroeckchen/SLEd as interface references, not copied code. No new dependencies or network access. Actual Android UI testing required.

## Persistent private draft library
The earlier memory-only workspace now supports explicit Save local draft, Save as a new local copy, Saved lorebooks (load/delete) and a creator guide. Up to 16 private drafts, each bounded to 8 MiB encoded data and the existing semantic limits. The versioned binary format preserves all supported fields, exact entry order, blank keys, Unicode, conversion-loss flag and skipped-disabled count. It does not reconstruct unsupported source fields. Android AtomicFile protects writes, store operations are process-serialized, UUID filenames cannot be chosen from user text, and listing reads only the short header. A failed load preserves the current draft, damaged records can be deleted, and deleting a saved copy leaves the open draft and exports intact. No background autosave, synchronization or automatic publication. Unsaved edits are still memory-only. Local draft files are removed on uninstall/clear data; export important books separately. Device storage and UI validation pending. See CREATOR_GUIDE_RESEARCH.md for source mapping.

## PNG character-card lorebook extraction
File picker recognizes PNG by signature, not extension or MIME. The streaming metadata reader supports standard uncompressed tEXt chunks named chara (V2) or ccv3 (V3), prefers ccv3, and refuses duplicate recognized chunks, broken CRCs, invalid Base64/UTF-8, trailing data and oversized inputs. Limits: 32 MiB PNG, 4096 chunks, 8 million encoded metadata bytes and 2 million decoded text characters. Image data is streamed for CRC checks, never decoded or rendered. Only embedded lorebook content goes into the existing JSON converter; full character profiles, images, assets, zTXt/iTXt and CHARX are not imported by this change. No remote asset retrieval or changes to original files. PNG structural checks are not full image validity checks. Tested on synthetic metadata fixtures, not Android or actual official import.
