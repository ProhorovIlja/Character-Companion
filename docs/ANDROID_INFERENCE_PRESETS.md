# Mandy AI — experimental Android CPU inference presets

Three explicit foreground presets: Low memory (2048 context tokens, 256 maximum output tokens, 2 CPU threads); Balanced (4096, 512, 4; preserves previous defaults); Longer context (6144, 768, 6). These are provisional settings, not measured Pixel 8a tuning. No thread affinity, GPU/NPU offload, automatic switching or resident model cache. The settings button in the independent workspace uses stable keys in private SharedPreferences, with Balanced on absent/invalid key; preserves the existing draft through the workspace writer. Generation snapshots the chosen preset before trust confirmation; explicit memory/relationship assessments use the selected context and threads, capped at 384 output tokens. Existing character and conversation data and legacy browser UI unchanged. No new dependencies/permissions.

The JNI symbol is explicitly versioned nativeGenerateV2 so an old native library fails linkage rather than interpreting mismatched arguments. Both Kotlin and C++ validate CPU thread count 1..8; llama context receives n_threads and n_threads_batch. No change to fixed prompt batch settings, GPU layers or sampler. The existing 12,000 UTF-16 history selection budget remains separate from token context. Tokenization can reject an oversized prompt instead of silently trimming the identity or history. The low-memory preset can therefore refuse a prompt accepted by Balanced. Context support depends on model training limits. Token-cap termination still does not commit a partial reply. Rebuild the Kotlin app and native library together.

Admission now scales the provisional workspace allowance upward from 768 MiB at 4096 tokens (minimum remains 768 MiB even for lower context); Longer context adds 384 MiB. Still a conservative estimate not actual GGUF model-specific memory or KV-cache calculation. Reject invalid context, implausible metrics and insufficient headroom. Native model verification before admission and pending retry behavior preserved; lower-level callers may omit admission. User can choose smaller models or lower context, not bypass guard. No automatic memory polling or monitoring.
